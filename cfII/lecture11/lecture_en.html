Part 1 — Accounts and access

Slide 5

Account = identity + data + access

Study the original slide first. Then read the web explanation.

An account is the system's digital identity for one user. It connects a name to files, messages, settings, and permissions. When you sign in, the system does not see your face or know your intentions. It trusts the account. If another person enters it, the system may treat that person as you. This is why account protection is also data protection and access control.

Slide 7

Permissions: what can this account do?

Study the original slide first. Then read the web explanation.

Permissions decide what an account or app can do. Read permission allows viewing. Change permission allows editing. Install permission can affect the system. No access blocks the action. These limits reduce damage from mistakes and misuse. A person may need to read one document without changing it, or use an application without installing new software. The safest permission is the minimum needed for the real task.

Part 2 — Authentication

Slide 13

Why passwords fail

Study the original slide first. Then read the web explanation.

Passwords fail in different ways. A short common password may be guessed. A password may be stolen by phishing or malware. A service may expose it in a data breach. Reuse can then spread one stolen password to several accounts. A password may also be seen on paper or on an unlocked screen. Good protection combines a long unique password with MFA, a passkey, and secure recovery settings.

Slide 14

Modern password guidance

Study the original slide first. Then read the web explanation.

Modern password guidance focuses first on length and uniqueness. A password does not become safe simply because it contains one capital letter, one number, and one symbol. A longer password or passphrase usually gives more possible combinations and is easier to remember correctly. Important accounts need different passwords. Change a password when there is evidence of compromise, not only because a calendar date has arrived.

Passphrase: long, memorable, not personal

Password reuse creates a chain reaction

Study the original slide first. Then read the web explanation.

Password reuse creates a chain reaction. Imagine that a small shopping website is breached. The attacker tries the same email and password on cloud storage, social media, and school systems. If the email account also uses that password, the attacker may reset other accounts and change recovery information. One weak service can therefore become the entrance to many important services. Password manager

A password manager stores many unique passwords in one protected vault. It can generate long random passwords and fill them only on the correct website. This reduces reuse and helps avoid typing a password into a fake domain. The vault still needs protection: use a strong master password, enable MFA when available, keep recovery information current, and protect the device where the manager is installed.

Three authentication factors

Study the original slide first. Then read the web explanation.

Authentication factors come from different categories. Something you know is a password or PIN. Something you have is a phone, security key, or trusted device. Something you are is a fingerprint or face. Two checks are strongest when they use different factors. Two passwords are still only two things you know. The purpose of MFA is to make one stolen secret insufficient for entry.

Slide 41

Four concepts students often confuse

Study the original slide first. Then read the web explanation.

Encoding, compression, encryption, and hashing can all change how data looks, but they solve different problems. Encoding changes representation so systems can store or transmit data. Compression reduces size. Encryption protects readable content with a key. Hashing creates a one-way fingerprint for comparison. Calling every changed file encrypted is dangerous because encoded or compressed information may still be easy for anyone to read.

Encoding

Study the original slide first. Then read the web explanation.

Encoding gives the same information a standard representation. Text characters are stored as numbers, and systems must agree on the encoding to display them correctly. UTF-8 is a common text encoding. QR codes and Base64 also represent information in another form. Encoding helps compatibility and transmission, but it is not secrecy. Anyone who knows the format can usually decode the information without a secret key.

Compression

Study the original slide first. Then read the web explanation.

Compression reduces file size by representing data more efficiently or removing detail that is less important. ZIP can compress documents, while JPEG, MP3, and video formats reduce media size in different ways. A smaller file is easier to store and send, but it is not automatically protected. A ZIP file without encryption can be opened by anyone who receives it. Compression and encryption may be used together, but they are different operations.

Slide 44

Encryption

Study the original slide first. Then read the web explanation.

Encryption changes readable data into protected data using a key. Without the correct key, the content should be unreadable. Decryption uses the key to restore the original information. The difficult part is often key management. If the key is stolen, an attacker may read the data. If the only recovery key is lost, the legitimate user may also lose access. Encryption therefore needs secure keys and a recovery plan.

Encryption protects data movement, but human decisions still control what happens at the ends.

Slide 48

Hashing: one-way fingerprint

Study the original slide first. Then read the web explanation.

Hashing creates a fixed digital fingerprint from data. A small change in the file should produce a different fingerprint, so hashes can help check integrity. Good systems also use protected password hashes instead of storing readable passwords. During login, the entered password is processed and compared with the stored result. Hashing is not normal encryption because it is designed for comparison, not for restoring the original content.

Part 5 — Backups and recovery

Slide 50

Security includes recovery

Study the original slide first. Then read the web explanation.

Security includes recovery because prevention is never perfect. Files may be deleted by mistake, storage may fail, a phone may be lost, an account may be locked, or ransomware may damage accessible data. A secure system does not only try to stop these events. It also keeps recoverable copies, protects recovery accounts, records what happened, and tests how normal work can return after the problem.

Slide 51

One copy is not a backup

Study the original slide first. Then read the web explanation.

One copy is a single point of failure. A second folder on the same laptop does not protect against a broken drive, theft, fire, or spilled drink. Syncing the same deletion to another device may also remove the file there. A backup is a separate recoverable copy. Separation may mean another device, another protected service, another location, an offline copy, or version history that can restore an earlier state.

Slide 52

The 3-2-1 backup rule

Study the original slide first. Then read the web explanation.

The 3-2-1 rule is a simple planning model: keep three copies of important data, use two different storage types, and keep one copy away from the main device. For a student, this might be the laptop, a protected cloud backup, and an external drive stored separately. The exact tools can change, but the important idea is that one accident should not destroy every copy at the same time.

Slide 53

Cloud, sync, and backup are not identical

Study the original slide first. Then read the web explanation.

Cloud storage, synchronization, and backup are related but not identical. Sync keeps current files similar across devices. If a file is deleted or damaged, that bad change may spread. A backup keeps recoverable versions or copies from an earlier time. Cloud services can provide backup features, but only when version history, retention, and account recovery are configured correctly. Check what the service actually protects instead of assuming that cloud means backup.

Slide 54

Offline or isolated backup limits ransomware damage

Study the original slide first. Then read the web explanation.

Ransomware may encrypt files on the computer and any connected drive or network location that the account can reach. A backup that is always connected can be damaged together with the main files. Keep at least one copy offline, disconnected, isolated, or otherwise protected from ordinary user access. Also protect backup accounts with unique passwords and MFA. The goal is to create a recovery copy outside the attacker's reach.

Part 6 — Incident response

Slide 58

One response flow for incidents

Study the original slide first. Then read the web explanation.

When an account or private information may be compromised, stop the unsafe action and preserve useful evidence without spreading the data further. Report what happened, when it happened, what was opened or shared, and whether a password or code was entered. From a safe device, protect the account, close sessions, and check recovery settings. If files were damaged, use the approved backup and recovery process. Fast honest reporting usually reduces damage.
